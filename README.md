# Жильё в Саудовской Аравии

Доска объявлений об аренде и продаже жилья для русскоязычных. Объявления собирает
парсер из телеграм-чатов; каждое публикуется со ссылкой на первоисточник.

Приложение работает в двух средах: как обычный сайт и как мини-приложение внутри
Telegram. Регистрации и паролей нет. Пришёл из Telegram — знаем, кто ты, из данных
мини-приложения. Пришёл из браузера — просто читаешь ленту.

## Запуск

```bash
npm install
npm run dev      # разработка
npm run build    # сборка в dist/
npm run preview  # посмотреть собранное
npm test         # расчёты сравнения
```

## Откуда берутся данные

```bash
VITE_API_BASE=                                   # пусто: public/listings.json, фильтры в браузере
VITE_API_BASE=https://realty-api.<аккаунт>.workers.dev   # задано: все запросы в Worker
```

Переменная читается **только на сборке**: на Cloudflare Pages её нужно задать
в настройках проекта и после этого пересобрать — у уже выложенной сборки значение
не поменяется.

Кавычки вокруг адреса не нужны. Если они всё же попали в значение (`"…"`, `«…»`
или `¨…¨` с нестандартной раскладки), фронт их срежет; но если после этого адрес
всё равно не разбирается, в консоли появится явная ошибка, а лента будет читаться
из `listings.json` — вместо молчаливых отказов на каждом запросе.

Если запросы не проходят и в интерфейсе «не получилось связаться с сервером»,
проверьте по порядку:

1. `curl https://realty-api.<аккаунт>.workers.dev/health` — Worker перечислит,
   что у него настроено, и ответит даже без базы; там же видно, каких таблиц
   не хватает, если забыли применить миграции;
2. консоль браузера — фронт пишет туда код ответа и код ошибки сервера
   (`Загрузка фотографии: сервер ответил 503 (no-migration)`), а не только
   общее сообщение из интерфейса.

Браузер не отличает недоступный сервер от запрещённого источника — в обоих случаях
это одинаковая ошибка сети. А `Error 1101` и «отсутствует Access-Control-Allow-Origin»
при коде 500 означают, что упал сам Worker: разбор в
[worker/README.md](worker/README.md#если-что-то-не-работает).

Единственное место, которое знает об источнике, — `src/lib/api.js`; компоненты вызывают функции и об источнике не знают.

Пока Worker не написан, функции записи возвращают `{ ok: false, reason: 'no-backend' }`,
а интерфейс прячет соответствующие кнопки — «Пожаловаться» не показывается вовсе.
Заявка не может «уйти в никуда».

### Файл парсера

`public/listings.json`:

```json
{ "generatedAt": "2026-09-01T06:00:00Z", "items": [ { "id": "...", "dealType": "rent" } ] }
```

Фронт защищён от парсера: объявления с прошедшим `expiresAt` в ленту не попадают,
отсутствующие поля заполняются умолчаниями в `normalizeListing`, пустой, битый
или отсутствующий файл даёт пустую ленту, а не белый экран.

Фотографий на первом этапе нет: `photos` пуст, вместо картинки — заглушка. Пропорции
блока заданы заранее (`aspect-ratio`), поэтому будущая загрузка фото из R2 не будет
сдвигать уже отрисованный список.

## Контракт Worker

```
GET  /listings?deal=rent&city=medina&district=awali&rooms=2
              &priceMin=&priceMax=&q=&cursor=&limit=20
     → { items, nextCursor, total }
GET  /listings/:id            → { item }
POST /listings                → { ok, id }
POST /listings/:id/report     → { ok }
```

Запросы на запись фронт отправляет с заголовком:

```
Authorization: tma <initData>
```

`initDataUnsafe` на клиенте используется только для интерфейса. Настоящая проверка —
на Worker: HMAC-SHA256 от строки `initData` с ключом, полученным из токена бота,
плюс проверка свежести `auth_date`.

`nextCursor` непрозрачный: сейчас это смещение в массиве, потом станет идентификатором
записи. Порядок выдачи — сначала `verified`, потом по `publishedAt` вниз.

**`src/lib/schema.js` копируется в проект Worker без изменений.** В нём нет ни импортов
React, ни браузерных API — только поля, справочники городов и районов, расчёты стоимости
и функция `queryListings`, которая задаёт порядок выдачи. Один файл на обе стороны —
единственный способ гарантировать, что после переезда лента не перетасуется.

## Структура

```
src/
  lib/
    schema.js     поля, города, районы, расчёты, фильтрация, порядок и проверка заявки — общий с Worker
    api.js        единственное место, знающее об источнике данных
    telegram.js   мини-приложение: тема, BackButton, ссылки, CloudStorage
    storage.js    настройки поверх CloudStorage с откатом на localStorage
    format.js     деньги, площадь, склонения, даты
  lib/compare.js  сравнение отобранного: строки, подсветка лучшего, выводы
  lib/adsFeed.js  отбор рекламы и её расстановка в ленте
  lib/image.js    уменьшение снимков перед отправкой
  ads.js          сами рекламные блоки — правится руками
  hooks/          лента с курсором, избранное, задержка поиска
  components/     шапка, карточки, шторки, форма заявки
```

## Расчёт стоимости

- `monthlyRent` — цена за год делить на 12.
- `trueMonthly` — (аренда за год + комиссия) / 12 + коммуналка за месяц.
- Залог в месячную стоимость не входит: он возвращается, поэтому идёт отдельной строкой.

Для продажи месячной цены нет — показывается полная стоимость.

## Хранение настроек

Город, фильтры и избранное лежат в `CloudStorage` телеграма, если он доступен,
иначе в `localStorage`. Доступность проверяется по версии клиента: `CloudStorage`
появился в 6.9, а в более старых методы есть, но молча не работают — без проверки
каждый ключ ждал бы своего таймаута на старте. CloudStorage привязан к аккаунту, поэтому настройки переезжают
между устройствами человека без всякой авторизации. Локальная копия пишется всегда —
она же откат, если облако молчит.

## Сравнение отобранного

Из «Избранного» (от двух сохранённых) открывается сравнение. Считается целиком
в браузере: ни базы, ни запросов на запись.

Сравниваются не поля объявлений, а деньги, которые человек на самом деле отдаст:
итог в месяц, цена за квадратный метр, сколько нужно разово при въезде (залог плюс
комиссия), сколько уйдёт за первый год. Залог из годовых расходов исключён — он
возвращается.

Что делает сравнение осмысленным, а не таблицей полей:

- **Ноль и «неизвестно» — разные вещи.** «Комиссии нет» — это лучшее значение,
  а отсутствующая площадь — прочерк, и в ранжировании такая строка не участвует.
  С данными из чатов это происходит постоянно.
- **Строки, одинаковые у всех, скрыты** переключателем «только различия»: смотреть
  надо на то, чем варианты расходятся.
- **Лучшее значение в строке подсвечено**, но только если победитель один: при ничье
  подсвечивать нечего.
- **Короткие выводы сверху** вместо чтения таблицы глазами — и каждый вывод появляется,
  только когда победитель действительно один. Самая дешёвая помесячно и самая дешёвая
  на въезде — обычно разные квартиры, и это как раз то, что стоит увидеть.
- **Аренда и продажа разведены**: сравнивать их между собой бессмысленно.

Расчёты живут в `src/lib/compare.js` — чистый модуль без React, покрыт `npm test`.

## Размещение объявления

Кнопка «+» в шапке появляется, когда задан `VITE_API_BASE`. Форма показывается только
внутри Telegram: заявку подписывает аккаунт человека, и в браузере подписать её нечем —
поэтому вместо формы там объяснение, а не поля, которые упрутся в отказ.

Заявка проверяется теми же правилами, что и на Worker: `validateSubmission` живёт
в общей `src/lib/schema.js`, поэтому клиент показывает ошибку сразу, а сервер остаётся
единственным, чьё слово решает. Отказы сервера (401, 422, 429, сеть) показываются
словами, а не молчанием.

После отправки объявление получает статус «на проверке»: в ленте его нет, автору оно
видно в разделе «Мои объявления» (`GET /my/listings`). Туда же ведёт строка в верху формы.

К заявке можно приложить до десяти фотографий. Снимки уменьшаются в браузере
до 1600 px и отправляются в R2 через Worker: телефонное фото весит 5–10 МБ,
а сервер принимает до пяти, так что без уменьшения загрузка отказывала бы.

## Реклама

`src/ads.js` — список рекламных блоков. Файл правится руками или собирается
в `ads-editor.html`; фронт его только читает.

```js
{ type: 'strip', color: 'gold', logo: 'data:image/jpeg;base64,…',
  title: 'Заголовок', text: 'Строка пояснения', url: 'https://…', until: '2026-12-31' }
```

- `type` — `strip` (компактная строка), `card` (карточка с логотипом),
  `banner` (цветная плашка с кнопкой), `image` (одна картинка).
- `color` — имя из палитры (`green blue purple orange red gold teal pink dark`)
  или свой цвет вида `#0A6CFF`. Незнакомое значение не ломает вёрстку.
- `until` — дата, после которой блок перестаёт показываться.

Блоки встают в ленту после третьего объявления, дальше через каждые шесть,
и не ставятся в самый хвост — иначе список выглядит оборванным. Когда действующих
блоков нет, показывается `placeholderAd`.

Логотип может быть ссылкой или полным data-URI. Обрезанный или битый заменяется
буквой на цветной подложке: браузер не должен ругаться в консоль и рисовать
разорванную картинку.

Правила отбора и расстановки лежат в `src/lib/adsFeed.js` и покрыты `npm test`.

## Города

Города и флаг их запуска — в `src/lib/schema.js`. Сейчас открыты Медина и Мекка,
остальные заведены, но выключены:

```js
{ id: 'medina', label: 'Медина', enabled: true },
{ id: 'jeddah', label: 'Джидда', enabled: false },
```

Выключенный город не показывается в выборе города и в фильтрах и не принимается
в заявках. Данные парсера по нему при этом можно копить заранее. Комментировать
код для этого не нужно — файл общий с Worker, поэтому фронт и сервер меняются
вместе и не могут разойтись. После правки скопируйте схему в Worker
(`cp src/lib/schema.js worker/src/schema.js`) и разверните обе части.

## Бэкенд

Worker лежит в `worker/` — Cloudflare Worker с D1 и R2, реализующий контракт выше.
Развёртывание, загрузка из парсера и принятые решения описаны в
[worker/README.md](worker/README.md).

## Хостинг

Cloudflare Pages: команда сборки `npm run build`, каталог `dist`. Роутера нет,
SPA-фолбэк не нужен. Переменную `VITE_API_BASE` задавать в настройках проекта Pages.

## Что проверено

23 теста на расчёты сравнения и рекламу (`npm test`), 54 теста на Worker. Сборка проходит без ошибок и предупреждений. В браузере (Chromium, 320/360/390 px)
проверены: лента и подгрузка по прокрутке, поиск с задержкой, фильтры (отмена
не меняет текущие), выбор города с запоминанием между запусками, избранное, тёмная тема.

Отдельно проверены четыре случая порчи данных: пустой `listings.json`, объявление
без фото, объявление без телефона, объявление с прошедшей датой — плюс битые записи
(отсутствующий `id`, неизвестный город, число строкой, `contact: null`) и 404 на файле
данных. Интерфейс ни в одном случае не падает.

Режим Worker проверен на фейковом сервере, реализующем контракт выше:
пагинация по курсору, деталь объявления, жалоба и заголовок `Authorization: tma`.

Telegram-среда проверена подделкой `window.Telegram.WebApp`: `ready`/`expand`, тема
из `themeParams`, BackButton закрывает шторку, ссылки `t.me` идут через
`openTelegramLink`, CloudStorage вместо `localStorage`.
